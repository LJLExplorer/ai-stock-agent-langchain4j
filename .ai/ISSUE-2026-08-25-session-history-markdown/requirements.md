# 会话历史与 Markdown 展示需求

## 背景

当前前端点击“新建会话”只清空本地状态，不会立即创建后端会话；已有会话也没有列表入口，用户必须手动记住 sessionId 才能恢复记录。后端返回的助手内容包含 Markdown，但前端按普通字符串直接显示。

## 目标

1. 点击“新建会话”立即创建真实会话并获得 sessionId。
2. 用户可以浏览、筛选和点击历史会话，恢复此前的聊天记录，不需要手动输入 sessionId。
3. 支持多个历史会话，并在会话创建、发送消息后及时更新列表。
4. 助手消息按 Markdown 格式渲染，用户消息保持纯文本展示。

## 验收标准

- 输入有效 userId 后点击“新建会话”，后端创建 `chat_sessions` 记录，前端切换到返回的 sessionId。
- 页面加载和 userId 变化后，历史区域自动获取该用户的会话列表；列表可滚动，按标题/股票代码筛选。
- 点击历史会话后，前端加载并展示该会话全部消息，恢复会话标题及股票代码。
- 新消息发送成功后，当前会话的标题、消息数、更新时间在历史列表中更新。
- 助手返回的标题、段落、列表、表格、引用、代码块等 Markdown 能正确渲染。
- 会话接口失败时不丢失当前前端消息，并向用户显示明确错误。
- 前端生产构建通过。

## 非目标

- 不增加会话删除、重命名、分页 API。
- 不改变后端消息内容格式，Markdown 仍由后端返回原文。
