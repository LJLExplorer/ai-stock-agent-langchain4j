# 运行日志可靠性修复需求

## 背景

2026-09-06 12:27:54 开始的最近一次成功启动中，深度投研请求暴露出异步执行状态、SSE 错误响应与模型输出稳定性问题。此前一次启动还记录了 Milvus 连接超时，最终答案生成阶段记录了外部模型请求超时。

## 目标

1. 深度投研接口返回 `202 Accepted` 前，持久化归属当前用户的 `PLANNED` 执行状态，使状态查询和 SSE 可以立即访问。
2. 后台规划完成后，以乐观锁安全替换预创建状态，不影响同步工作流首次插入语义。
3. SSE 请求遇到不存在或无权访问的 executionId 时直接返回 404，不再由全局 JSON 异常响应触发媒体类型异常。
4. 对包含明确六位股票代码的请求优先使用现有受限解析器生成白名单计划，避免为确定性输入调用 Planner 后得到空响应。
5. Judge 输出不符合 JSON 契约时保留确定性安全降级，同时记录可定位但不泄漏模型正文的稳定原因。
6. 明确区分代码可修问题与 Milvus、外部模型网络超时等运行环境问题。
7. 明确六位股票代码的请求不得先阻塞在 Query Rewrite 模型调用上。
8. 深度投研前端进度必须来自后端真实完成事件，不使用固定阶段或计时器伪造增长。
9. 深度研究只运行本轮证据覆盖的领域专家，独立专家并行执行；未请求板块不得被描述成缺失或损坏。
10. 回答中的 evidenceId 必须展示为普通用户可理解的证据来源，并在存在原文 URL 时支持直接打开。

## 功能需求

### 异步执行状态

- `ResearchExecutionService.start` 在提交后台工作前保存包含 executionId、sessionId、userId、原问题与 `PLANNED` 状态的占位记录。
- 占位状态与正式执行状态必须使用同一规范化执行问题；`orderId` 已出现在消息中时不得重复追加。
- 队列拒绝或后台失败时，占位记录必须转换为 `FAILED`，不能永久停留在 `PLANNED`。
- `WorkflowRunner.run` 仅允许替换同 executionId、同 userId、同 sessionId、无计划且仍为 `PLANNED` 的占位记录。
- 已存在的非占位记录必须拒绝覆盖。
- 同步 `/api/chat/send` 仍按首次插入方式启动工作流。

### SSE 错误响应

- 不存在和无权访问继续统一返回 404，避免泄漏 executionId 是否存在。
- `ResponseStatusException` 必须保留原始 HTTP 状态并返回空响应体。
- `Accept: text/event-stream` 的 404 不得触发 `HttpMediaTypeNotAcceptableException`。

### Planner 确定性快速路径

- 用户原文已有六位股票代码时，Query Rewrite 直接使用原问题并确定话题边界。
- 用户消息包含明确六位股票代码时，先调用 `PlannerTextParser` 从用户原文生成受限计划。
- 本地计划仍必须经过 `PlanValidator`。
- 本地无法形成有效计划时再调用模型 Planner，保留复杂请求兼容性。
- 不扩大允许的意图、任务或工具集合。

### Judge 降级诊断

- 无 JSON 对象、JSON 解析失败、字段缺失、枚举非法、置信度非法、日期非法、未来日期和未知 evidenceId 使用不同稳定原因码。
- 日志只记录原因码、异常类型和响应长度，不记录模型正文。
- 不增加 Judge 调用次数，不改变既有固定调用上限。

### 真实执行进度与审议范围

- 异步接口接收只发布 `EXECUTION_ACCEPTED`，不得在实际审议前发布 `DEEP_RESEARCH_STARTED`。
- `PLAN_CREATED` 提供受控的任务数量元数据。
- 深度研究按 EvidencePack 的 `FINANCIAL`、`TECHNICAL/MARKET`、`NEWS` 类型选择领域专家，并始终保留看多、看空和风险角色。
- 独立专家并行执行，Judge 仅在全部专家结束后执行一次；不得把未请求板块作为数据缺失风险。
- 实际启用的研究角色及 Judge 必须各自发布开始与完成事件，不携带模型正文；开始事件提供本轮 `roleCount`。
- 前端按计划、实际工具终态、证据包、实际角色/Judge 完成和答案就绪事件计算完成步数与百分比，并显示活动角色及真实耗时。
- 重复或重放事件不得重复增加进度；成功终态前进度不得显示 100%。

### 证据来源展示

- EvidencePack 中未被拒绝的事实映射为 `KnowledgeSource`，保留 evidenceId、来源名、摘要、时点及原文 URL。
- `[evidence:ev-...]` 在界面显示为“证据：来源名”，有 URL 时直接打开原文，无 URL 时定位到来源项。
- 助手消息持久化本轮来源，重新加载会话后仍可查看。
- 模型请求和响应正文默认继续显示 `<redacted>`，不得为排查耗时而关闭脱敏。

## 非目标

- 不修改或提交 `src/main/resources/application.yml`。
- 不隐藏仍然发生的外部服务错误。
- 不把 Milvus 改成内存向量库，也不改变 RAG 数据语义。
- 不保证第三方模型永不超时或永远返回合法 JSON。
- 不重构整个 Agent 模型配置体系。

## 验收标准

- 后台线程被阻塞时，异步启动返回前已能通过 `findOwned` 读取占位状态。
- 后台规划完成后，占位状态被完整工作流状态替换，且乐观锁版本正确。
- 独立传入 `orderId` 和消息已含代码两种请求都能通过严格占位校验。
- SSE 缺失 execution 的 MockMvc 请求返回 404，无二次媒体类型异常。
- 明确代码请求不调用模型 Planner，生成的任务仍受白名单校验。
- 明确代码请求不调用 Query Rewrite；异步接收不会提前显示进入多角色审议。
- Judge 各类格式失败得到稳定、可测试的原因码并安全降级。
- 进度条仅由去重后的后端完成事件推进，角色开始事件能显示当前正在执行的角色。
- 仅技术证据时基本面与新闻角色零调用，技术、多空、风险角色可并发到达，Judge 最后单次汇总。
- 技术证据标签可读、可点击，右侧来源区展示对应来源，消息重新加载后来源仍存在。
- 相关定向测试、完整 Maven 测试、前端测试与构建、`git diff --check` 通过。
- 最终报告单独列出无法由仓库代码根治的 Milvus/LLM 网络问题。
