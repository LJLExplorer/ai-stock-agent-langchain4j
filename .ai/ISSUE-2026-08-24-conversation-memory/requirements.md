# 会话记忆与 RAG 诊断需求

## 背景

当前项目使用 MongoDB 保存 LangChain4j 会话记忆和业务展示消息，但缺少高效的短期记忆摘要机制、用户级长期记忆以及可用于定位 RAG/模型问题的诊断信息。

本 Issue 以 `HEAD(main)` 为实现基线。工作区中此前生成的未提交记忆代码属于草稿，不能作为本 Issue 的实现依据。

## 目标

### 短期记忆

- 使用 Redis 保存会话短期记忆。
- 使用 `userId + sessionId` 隔离同一用户的多个会话。
- 采用滑动窗口保证即时对话连贯性。
- 按字符数控制窗口，默认上限 32,000 字符。
- 超限时生成滚动摘要，并保留最新窗口内容。
- 保留 LangChain4j 工具调用相关消息，避免消息链断裂。
- Redis 数据默认设置 24 小时 TTL。

### 长期记忆

- 仅支持用户主动录入，避免自动提取造成不可控记忆。
- 使用 EmbeddingModel 向量化并写入 Milvus。
- 使用 MongoDB 保存原文、用户归属、标签和向量 ID。
- 按用户 ID 和语义相似度召回长期记忆。
- 支持查询、召回和删除。

### RAG 诊断

- 每次启用 RAG 的对话保存一条轻量诊断记录。
- 记录检索数量、最高相似度、来源 ID/标题、上下文长度、回答长度、事实核查置信度和错误信息。
- 通过会话 ID、消息 ID 关联诊断记录。
- 不保存完整模型输入、完整模型输出或完整增强上下文。
- RAG 诊断异常不能阻断普通对话主流程。

## 非目标

- 不实现自动从对话中提取长期记忆。
- 不替换现有 MongoDB 业务消息历史。
- 不保存完整模型 Prompt、完整模型回答或敏感原文用于链路追踪。
- 不在本 Issue 中改造知识库文档同步和分块策略。

## 验收标准

1. 相同用户的不同 session 在 Redis 中相互隔离。
2. Redis 短期记忆可写入、读取、删除，并保留 LangChain4j 消息类型。
3. 短期记忆超过字符上限后，摘要和最新窗口均可恢复，且同一批历史不会每轮重复摘要。
4. 用户可以主动新增、查询、语义召回和删除自己的长期记忆。
5. 用户无法召回或删除其他用户的长期记忆。
6. 长期记忆服务不可用时，普通聊天仍能完成。
7. RAG 启用时产生轻量诊断记录，能够区分“无召回/低分召回/召回正常但回答异常”。
8. RAG 诊断写入失败不影响对话响应。
9. `mvn test` 和 `mvn -DskipTests compile` 通过。
