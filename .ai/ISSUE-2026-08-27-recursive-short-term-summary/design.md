# 递归短期摘要设计

## 数据流

```text
Redis 消息窗口超限
  -> 读取旧摘要 + 窗口前半段消息
  -> ConversationSummaryAssistant 生成新的结构化摘要
  -> 校验摘要非空且不超过预算
  -> 原子更新：保留窗口后半段 + 写入新摘要

新一轮对话
  -> 读取递归摘要 + 长期记忆
  -> 作为 StockAnalysisAssistant 的 SystemMessage 变量
  -> Redis 窗口原始消息 + 当前原始用户消息由 ChatMemory 处理
```

## 组件

- `ConversationSummaryAssistant`：无记忆、无工具的 LangChain4j AI Service。提示词要求输出结构化中文摘要，并设定字符预算。
- `ShortTermSummaryService`：将旧摘要和淘汰消息传给摘要器；生成失败、空结果或超过预算时抛错，由现有回滚逻辑保留窗口。
- `StockAnalysisAssistant`：普通和 RAG 方法均增加 `memoryContext` 模板变量，将短期摘要/长期记忆放在系统消息中。
- `ChatService`：不再把记忆上下文拼接至用户消息；调用对应的带上下文方法。删除会话时清理短期摘要。

## 错误处理

- 摘要模型异常、空文本或超出配置预算：本次不淘汰 Redis 消息；下轮仍可重试。
- 长期记忆召回异常：沿用现有降级逻辑，只跳过长期记忆。
- 摘要为空时，系统消息中的“历史上下文”保持为空，不影响正常对话。

## 测试

- 摘要单测验证旧摘要与淘汰消息均进入生成器、生成结果替换旧摘要、超预算时窗口不变。
- 对话服务测试验证摘要不进入用户消息，并被传给普通/RAG 助手的系统上下文变量。
- 清理测试验证会话删除会删除摘要和摘要进度。
