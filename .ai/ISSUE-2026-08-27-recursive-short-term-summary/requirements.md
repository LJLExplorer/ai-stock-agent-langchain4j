# 递归短期摘要需求

## 背景

现有 Redis 短期记忆在字符数超限后移除窗口前半部分，但默认摘要器仅拼接原文并从末尾截取。最早的关键事实会丢失，且摘要作为用户消息拼入本轮输入后会被再次写入消息窗口。

## 目标

- 超过短期记忆字符阈值时，使用模型将“已有摘要 + 本次淘汰的消息”压缩为新的滚动摘要。
- 摘要必须保留已确认事实、用户偏好、约束、结论与待办；不能依赖末尾字符串截断。
- LLM 每轮同时得到递归摘要、Redis 最近原始消息窗口和当前原始用户问题。
- 摘要以系统上下文传入，不持久化为 LangChain4j 的用户消息。
- 删除会话时同时删除消息窗口、摘要和摘要进度。

## 非目标

- 不改变 MongoDB 业务消息历史。
- 不自动把对话内容写入用户长期记忆。
- 不改变 RAG、工具调用或长期记忆的召回协议。

## 验收标准

1. 摘要器收到上一版摘要和本次淘汰消息，并产出替换后的摘要。
2. 摘要结果超出预算或生成失败时，Redis 原始窗口不被删除。
3. 模型调用的当前用户消息不含历史摘要；历史摘要只位于系统消息。
4. 非 RAG 与 RAG 对话均能获得短期摘要上下文。
5. 删除会话后，消息、摘要和进度 Key 均被清理。
