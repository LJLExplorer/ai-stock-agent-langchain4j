# Milvus 混合检索需求

## 背景

知识库 RAG 当前只通过 LangChain4j `EmbeddingStore.search` 在 Milvus 上执行稠密向量语义检索。精确术语、股票代码和缩写无法参与关键词召回，也没有融合两路候选的最终排名。

## 目标

在 Milvus 2.5.4 上使用原生 BM25 Function、稠密语义向量和 Hybrid Search，将语义与关键词两路检索结果用 RRF 融合并按最终分数返回。

## 功能需求

1. 知识分块写入 Milvus 时必须同时保存原始文本、稠密向量及由 Milvus BM25 Function 生成的稀疏向量。
2. 检索时必须并行执行稠密向量 ANN 查询与 BM25 稀疏向量查询。
3. 必须使用 Milvus `RRFRanker` 融合两路排名；同一分块在两路命中时，RRF 分数为两路 `1 / (k + rank)` 的和。
4. 检索结果按 RRF 总分降序，返回内容、来源元数据、语义分数、BM25 分数与 RRF 分数。
5. 未命中任一路时仍使用另一路结果；任一可恢复查询失败不得中断 RAG 对话。
6. 已禁用、删除中或已删除知识文档不可出现在最终结果中。

## 验收标准

- 同时命中语义和 BM25 的分块在 RRF 排名中优先于只命中一路且名次相近的分块。
- 股票代码和精确术语可通过 BM25 参与召回。
- 现有 `/api/rag/search` 和 RAG 管道保持 API 可用，并返回融合后的结果。
- 定向测试、完整 Maven 测试和 `git diff --check` 通过。
