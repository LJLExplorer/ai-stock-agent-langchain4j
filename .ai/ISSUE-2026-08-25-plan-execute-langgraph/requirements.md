# Plan-and-Execute 工作流需求

## 背景

当前项目已具备 Planner、PlanValidator 和 Tool 白名单裁剪，但最终仍由 LangChain4j `AiServices` 自主完成工具调用，缺少显式的执行状态、节点编排、结果反思和断点恢复能力。

## 目标

使用 LangGraph4j 构建股票分析版 Plan-and-Execute 工作流，并使用 MongoDB 持久化执行状态，使复杂股票分析过程可追踪、可重试、可恢复。

## 范围

第一版只覆盖股票分析场景：行情、技术分析、财务分析和新闻分析。订单、物流和客服工单不在本次实现范围内，但任务节点和状态模型应可扩展。

## 功能需求

1. Planner 生成的计划经过现有 `PlanValidator` 校验后，转换为工作流任务图。
2. 工作流具有明确的节点、状态、边和终止条件。
3. 行情、技术、财务和新闻等无依赖任务支持并行执行；Reflector 等待任务结果后再运行。
4. 每个任务和工作流状态均持久化到 MongoDB，支持服务重启后恢复未完成执行。
5. 任务执行必须具备幂等保护，恢复时不得无条件重复调用已经成功的任务。
6. Reflector 校验结果是否为空、标的是否一致、时间字段是否存在、工具是否报错。
7. 校验失败时支持有限次数重试；数据缺失时可动态追加允许的补充任务。
8. 工作流异常、超出重试次数或无法恢复时进入 FAILED，并返回可理解的错误信息。
9. 保留现有对话 API、RAG、会话记忆和工具调用展示能力。
10. README 更新架构图、执行状态、恢复机制和面试说明。

## 验收标准

- 合法股票分析计划可创建并运行完整工作流。
- 独立分析任务可并行执行并在 Reflector 汇合。
- 中断后可根据 executionId 从 MongoDB 恢复。
- 已完成任务恢复时不会重复调用工具。
- 空结果、错误结果和不一致标的可触发重试或补充任务。
- 重试上限、非法任务和不可恢复异常均可控失败。
- 新增测试和完整 Maven 测试通过。
