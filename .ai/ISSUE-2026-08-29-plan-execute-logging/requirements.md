# Plan-and-Execute 结构化日志需求

## 背景

系统已经使用 Planner 生成并校验任务计划，并在可用时交给工作流执行。但日志只覆盖 Planner 原始输出和部分失败情况，无法从单次请求清晰追踪计划到执行的转换过程。

## 目标

为整个对话链路增加可关联的诊断日志，支持定位模型调用、计划选择、工作流循环、工具调用和最终回答。

## 范围

1. 为每个聊天请求生成 `traceId`，并在请求、会话、RAG、规划、执行和回答阶段关联输出。
2. 记录每次实际模型请求与响应，包括提示词、模型文本、模型原始 tool call 和 tool result message。
3. 记录经校验后准备执行的计划：会话 ID、执行 ID、标的和任务名称。
4. 记录工作流开始、节点路由、循环、重试、结束及恢复执行的生命周期。
5. 记录每次工具调用的名称、参数、完整输出、成功状态、耗时和异常。
6. 默认完整记录内容，同时支持以配置限制单条内容长度，防止异常日志量失控。

## 验收标准

1. 一次请求可按 `traceId`、`sessionId` 和 `executionId` 串联完整链路。
2. 可在日志中看到模型调用前后的内容，以及模型选择工具时的原始 tool call。
3. 可在日志中看到每次工具调用的输入、完整输出、耗时与异常。
4. 可在日志中看到 `RETRY`、`ADD_NEWS` 到 `INIT` 的循环和尝试次数。
5. 正常完成、失败和恢复执行均输出相应生命周期日志。
6. 现有聊天和工作流行为保持不变，相关单元测试通过。
