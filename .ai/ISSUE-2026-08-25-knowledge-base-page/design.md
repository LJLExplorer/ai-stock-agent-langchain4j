# 知识库管理页面设计

## 方案选择

采用方案 B：引入 `react-router-dom`，建立标准路由结构。

相比在单个 `App.jsx` 中手写路径判断，React Router 能提供稳定的浏览器历史栈、直接 URL 访问、嵌套路由扩展能力，后续可自然增加会话详情、系统设置等页面。当前只增加两个路由，不引入额外状态管理框架。

## 前端架构

- `main.jsx` 使用 `BrowserRouter` 包裹应用。
- `App.jsx` 负责共享顶栏和路由出口。
- 现有问答内容抽取为问答页组件，路径为 `/`。
- 新增知识库页组件，路径为 `/knowledge`。
- 顶栏使用 `NavLink` 展示“问答 / 知识库”，并用 active 状态表达当前位置。
- 知识库页内部维护表单、文档列表、加载状态和操作反馈，不影响问答页的会话状态。

## 知识库页面布局

桌面端使用“左侧新增表单 + 右侧文档列表”的两栏布局；小屏幕改为上下堆叠。页面顶部显示知识库标题、RAG 说明和当前文档数量。

新增表单字段：

- 标题：必填，最多 200 字符。
- 文档类型：必填，默认 `MANUAL`，提供 FAQ、技术文档、SOP、政策规则等选项。
- 标签：可选，使用逗号分隔。
- 正文：必填，提示文本将被切块并向量化。

列表卡片显示标题、类型、标签、chunk 数、更新时间、状态。启用文档显示“禁用”操作，已禁用文档显示不可用状态；删除操作始终可见但需要确认。

## 后端数据流

### 新增

前端发送 `{ title, content, documentType, tags, metadata: {} }`。服务层执行现有分块和 Embedding 流程后保存文档与向量；异常向前端返回明确错误。

### 查询

新增 `findAll()` 查询全部未删除文档，控制器的 `GET /documents` 改为返回启用和已禁用记录，按照更新时间倒序返回，便于管理页面展示完整状态。

### 禁用

服务层读取文档，先删除 `vectorIds` 对应的 Milvus 向量；向量全部清理成功后将 `enabled=false`、`vectorIds=[]`、`chunkCount=0` 写回 MongoDB。向量清理失败时不改变启用状态，并返回错误，避免 RAG 与管理状态不一致。

### 删除

沿用现有两阶段删除流程；当文档已禁用且 `vectorIds` 为空时，删除操作应可幂等完成。接口对不存在文档返回 404 或明确的失败结果，避免前端误报成功。

## 错误处理与可访问性

- 所有表单字段有可见 label，不依赖 placeholder 作为唯一说明。
- 保存、禁用、删除时禁用对应操作并显示处理中。
- 错误信息显示在操作区域附近，成功信息使用 `aria-live="polite"`。
- 删除使用确认对话框；保留返回问答的明确导航。
- 保持现有颜色和间距 token，使用 lucide-react 图标，不使用 emoji。

## 测试与验证

- 后端：为查询全部、禁用时清理向量、向量清理失败不落库、删除幂等补充单元测试或控制器测试。
- 前端：至少通过生产构建；如项目现有测试基础不足，使用可独立测试的 API 辅助逻辑并以构建作为最低验证。
- 手工验证：问答 ↔ 知识库路由、刷新直达 `/knowledge`、新增、禁用、删除和窄屏布局。
