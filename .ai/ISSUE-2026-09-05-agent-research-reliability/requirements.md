# Agent 投研可靠性与深度研究模式需求

## 背景

当前项目已经具备受控 Planner、Java 白名单校验、LangGraph4j 工作流、话题级短期记忆、用户长期记忆，以及 Parent/Child Hybrid RAG。与 LangGraph、TradingAgents、FinRobot、RD-Agent、AgentScope Java 和 Spring AI Alibaba 等项目相比，当前优势是领域流程可控、Java 工程边界清晰，但仍缺少逐节点恢复、统一金融证据链、历史时点约束、Agent 效果评测、执行事件流、决策复盘和受控多角色审议。

本次改造采用渐进式增强，不整体迁移框架。默认请求继续使用现有受控流程；只有显式开启深度投研模式时，才执行多角色分析与审议。

## 目标

1. 将工作流持久化从首尾快照提升为逐节点 Checkpoint，并为外部工具增加幂等记录。
2. 建立统一的 `AnalysisContext`、`FinancialFact` 与不可变 `EvidencePack`，让数值由代码和数据源产生，LLM 只负责解释、质疑与综合。
3. 引入 point-in-time 数据契约，保证历史分析不会读取分析日期之后的数据。
4. 在答案保存前校验数字、日期和关键结论与证据的映射关系。
5. 提供类型化运行事件与 SSE 查询能力，使长任务进度可观察、可恢复。
6. 建立与聊天记忆隔离的研究决策及后验复盘记忆。
7. 新增可选深度投研模式，通过受控分析角色、多空审议、风险审查和 Judge 输出结构化结论。
8. 建立可重复的离线 Agent Eval，覆盖计划、话题、检索、证据和流程质量。
9. 在 README 中使用独立且醒目的章节说明上述增强，不把关键亮点藏在零散条目中。

## 功能需求

### 1. 分析上下文与历史时点

- 请求可选携带 `analysisDate` 与 `researchMode`，旧请求保持兼容。
- 未指定 `analysisDate` 时使用系统确定的当前日期；解析结果统一进入 `AnalysisContext`。
- `AnalysisContext` 至少包含股票代码、分析日期、研究模式、executionId、traceId 和用户/会话标识。
- 行情、K 线、财报、新闻和 RAG 证据均携带数据时点，不得将分析日期之后的数据加入 EvidencePack。
- 无法证明发布时间或报告期的数据必须标记时间状态，不能伪装成已通过 point-in-time 校验的证据。

### 2. 金融事实与证据包

- 新增统一的 `FinancialFact`，至少包含 metric、value、unit、currency、period、asOf、source、retrievedAt、formula、inputSnapshotId 和 evidenceId。
- 工具结果应保留结构化事实；面向模型或前端的文本由独立格式化层生成。
- `EvidencePack` 汇总工具事实、新闻来源、RAG 来源、缺失项和数据截止时间。
- EvidencePack 完成后不可被分析角色修改；多角色只能基于同一份证据进行判断。
- 部分数据源失败时允许生成部分证据包，但必须显式列出缺失维度和失败原因。

### 3. 节点级 Checkpoint 与幂等

- INIT、每个任务节点、REFLECTOR、CRITIC、RETRY/ADD_NEWS、ANSWER 和 FAILED 完成后保存执行状态。
- Checkpoint 保存继续使用版本条件更新，冲突不得静默覆盖。
- 执行状态增加 graphVersion、planHash、lastCompletedNode 和必要的恢复信息。
- 外部工具执行使用 `executionId + taskId + attempt` 幂等键；已有成功记录时恢复结果，不重复调用。
- Checkpoint 保存失败时不得将对应节点视为已完成。
- 恢复时必须校验图版本和计划摘要；不兼容状态进入可解释失败，而不是在不同图结构上盲目继续。

### 4. 类型化运行事件

- 定义稳定的运行事件类型，包括计划创建、节点开始/完成、工具开始/完成、重试、证据包完成、回答增量、工作流完成/失败。
- 事件必须携带 executionId、traceId、时间、序号和不含敏感正文的摘要字段。
- 保留现有同步 `/api/chat/send`；深度投研新增异步启动接口，立即返回 executionId 和 sessionId，后台继续执行。
- 提供基于 executionId 的 SSE 订阅和当前执行状态查询。
- SSE 连接断开不得取消后台执行；重新连接后可先读取持久化状态，再接收新事件。

### 5. Claim–Evidence 质量门禁

- 深度投研结论使用结构化输出，数字、日期和关键判断引用 evidenceId。
- 默认工作流答案也要检查可识别数字与来源覆盖情况。
- 第一次校验失败时允许基于失败原因重写一次；第二次仍失败时使用确定性降级文本，并保留工具明细与来源。
- 现有 Markdown `AnswerQualityGuard` 继续负责格式质量；新的证据校验不得与格式校验混为一体。
- 现有关键词式 `RagPipelineService.factCheck` 不作为可靠事实校验，应由新的证据覆盖机制替代或明确废弃。

### 6. 决策复盘记忆

- 新增与聊天消息、用户偏好记忆分离的 `ResearchDecision`。
- 记录股票、分析日期、结论、置信度、证据摘要、模型/图版本和证据哈希。
- 当后续市场数据覆盖配置的评估窗口时，计算标的收益与基准相对收益，并保存结构化复盘。
- 下一次分析同一标的时，只召回已完成且通过用户和标的隔离的复盘；不得把未来收益泄漏到历史时点分析。

### 7. 可选深度投研模式

- 默认模式沿用现有 Planner、确定性工具和工作流答案链路。
- 深度模式在 EvidencePack 完成后运行基本面、技术面和新闻分析角色。
- Bull 与 Bear 分别提出支持与反对证据；Risk Reviewer 检查风险、数据缺口和不确定性；Judge 输出最终结构化结论。
- 所有角色均为无工具、无会话记忆的只读分析器，只能访问同一 EvidencePack。
- 审议轮数固定且有严格调用上限；任一角色失败时可降级为现有受控回答，不影响业务消息和证据展示。
- Judge 输出至少包含评级、置信度、多方依据、空方依据、风险、缺失信息、证据 ID 和数据截止时间。

### 8. Agent Eval

- 建立离线固定样本，分别评估 Planner、话题路由、RAG、证据校验和工作流恢复。
- 指标至少包括任务/标的正确率、话题关系准确率、Recall@K、nDCG、引用覆盖率、数字一致性、工具成功率、延迟和模型调用次数。
- 默认 CI 不调用真实模型或外部金融接口；在线评测通过显式 Maven Profile 运行。
- 评测结果使用结构化报告，支持与历史基线比较；没有数据时不得在 README 宣称准确率或收益提升。

### 9. README 与面试材料

- README 新增一级独立章节“可靠 Agent 运行时与金融证据闭环”，不得只放在能力列表中。
- 独立展示节点级恢复、EvidencePack、point-in-time、Claim–Evidence、事件流、决策复盘、深度投研和 Eval。
- 架构图同时展示默认模式与深度模式。
- 简历和面试材料只描述已完成且有测试证据的功能，明确多角色审议不是自主交易。

## 非目标

- 不实现自动下单或任何资金操作。
- 不引入任意代码执行或通用沙箱。
- 不整体迁移到 CrewAI、AgentScope Java、Spring AI Alibaba 或其他 Agent 框架。
- 不实现分布式 A2A、多实例分布式锁或完整 MCP 平台。
- 不修改或提交 `src/main/resources/application.yml`。
- 不宣称无评测依据的准确率、收益率、并行提速或生产级高可用。

## 验收标准

- 每个工作流关键节点均有可验证 Checkpoint，恢复不会重复执行已成功工具。
- 历史分析中的证据均不晚于 analysisDate，未知时间来源被显式标记。
- 工具产生结构化金融事实，并能组装成不可变 EvidencePack。
- 最终数字与结论能够追溯到 evidenceId；无依据输出被重写或降级。
- SSE 能按顺序展示运行事件，断连不取消后台执行。
- 深度投研异步启动接口在工作完成前返回 executionId，旧同步接口保持兼容。
- 研究决策与聊天记忆隔离，并能在无时间泄漏的前提下形成后验复盘。
- 默认模式保持兼容；深度模式按固定角色与调用上限完成或安全降级。
- 离线评测和相关单元/组件测试通过，完整 Maven 测试及前端构建通过。
- README 和面试材料存在醒目的独立章节，描述与实现一致。
