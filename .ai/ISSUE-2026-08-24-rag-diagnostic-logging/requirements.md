# RAG 轻量诊断改为日志记录

## 背景

当前 RAG 诊断记录通过 `RagTraceService` 写入 MongoDB。诊断数据主要用于问题排查，实际排查由人工查阅应用日志完成，不需要额外查询数据库。

## 需求

1. RAG 诊断详细信息改为记录到应用日志。
2. 不再将 RAG 诊断记录写入 MongoDB。
3. 保留现有调用方使用方式，诊断记录失败不得影响正常对话或 RAG 主流程。
4. 日志至少包含 traceId、用户/会话标识、查询内容、命中数量、最高相似度、来源标识/标题和上下文长度等排查信息。
5. 增加测试，覆盖日志诊断服务不依赖数据库以及异常隔离行为。

## 验收标准

- RAG 诊断路径不再调用 `MongoTemplate` 保存数据。
- 人工通过应用日志可以定位一次 RAG 检索的关键上下文和命中情况。
- 现有 RAG 与对话流程行为不变。
- 相关测试通过。
